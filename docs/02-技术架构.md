### 架构层次

#### 1. 扩展主机层 (Extension Host)
- **运行环境**: Node.js 环境
- **主要职责**: 业务逻辑处理、VSCode API 调用、系统资源访问
- **核心组件**: Controllers、Services、Providers

#### 2. 通信层 (Communication Layer)
- **框架**: CEC Client-Server
- **主要职责**: 扩展主机与 Webview 之间的双向通信
- **通信模式**: RPC 调用、事件订阅

#### 3. 用户界面层 (UI Layer)
- **技术栈**: React + Ant Design
- **主要职责**: 用户交互界面、状态管理、事件处理
- **运行环境**: Webview 容器

#### 4. 外部服务层 (External Services)
- **可选服务**: NestJS 服务器、Playwright 测试
- **主要职责**: 扩展功能支持、第三方集成

## 架构设计原则

### 1. 分层架构
- **清晰的层次划分**: UI 层、业务逻辑层、数据访问层
- **单向依赖**: 上层依赖下层，避免循环依赖
- **接口隔离**: 通过接口定义层间交互

### 2. 模块化设计
- **功能模块化**: 按功能划分独立模块
- **服务模块化**: 按职责划分服务组件
- **组件模块化**: UI 组件独立封装

### 3. 依赖注入
- **控制反转**: 通过 TSyringe 实现依赖注入
- **生命周期管理**: 自动管理服务实例生命周期
- **测试友好**: 便于单元测试和模拟

### 4. 事件驱动
- **异步通信**: 基于事件的异步通信机制
- **解耦合**: 减少组件间的直接依赖
- **可扩展**: 易于添加新的事件处理器

## 性能架构

### 1. 异步处理
- **非阻塞操作**: 所有 I/O 操作都是异步的
- **并发控制**: 合理控制并发数量
- **错误隔离**: 异步操作的错误不影响主流程

### 2. 资源管理
- **内存管理**: 及时释放不需要的资源
- **连接池**: 复用网络连接和数据库连接
- **缓存策略**: 合理使用缓存减少重复计算

### 3. 懒加载
- **按需加载**: 功能模块按需加载
- **代码分割**: 前端代码按路由分割
- **资源优化**: 图片和静态资源懒加载

## 安全架构

### 1. 权限控制
- **最小权限原则**: 只请求必要的 VSCode 权限
- **沙箱执行**: 在受控环境中执行外部命令
- **输入验证**: 严格验证用户输入

### 2. 数据安全
- **本地存储**: 敏感数据仅存储在本地
- **传输加密**: 网络请求使用 HTTPS
- **数据脱敏**: 日志中不包含敏感信息

### 3. 错误处理
- **异常捕获**: 全局异常处理机制
- **错误恢复**: 自动恢复机制
- **安全降级**: 出错时的安全降级策略

## 扩展性架构

### 1. 插件机制
- **控制器扩展**: 易于添加新的控制器
- **服务扩展**: 支持自定义服务注册
- **UI 扩展**: 支持自定义 UI 组件

### 2. 配置系统
- **动态配置**: 支持运行时配置更新
- **环境配置**: 支持不同环境的配置
- **用户配置**: 支持用户自定义配置

### 3. 钩子系统
- **生命周期钩子**: 支持生命周期事件监听
- **业务钩子**: 支持业务流程的钩子扩展
- **UI 钩子**: 支持 UI 渲染的钩子扩展
